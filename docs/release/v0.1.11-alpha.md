# TreasureRun v0.1.11-alpha — Server safety hardening

This alpha release strengthens the existing single-player round flow before the separate server-hosted create/join milestone.

## Changes

- Isolated mutable game-stage generation in the plugin-owned `treasurerun_arena` world.
- Added explicit round lifecycle states and a unified cleanup path.
- Rejected duplicate starts from preparation onward.
- Restored players to their saved world and location after cleanup.
- Selected unique chest columns before changing arena blocks.
- Stopped preparation safely when the configured chest count cannot be placed.
- Restored chest target and supporting blocks during cleanup.
- Applied the op-only `treasure.admin` contract to round start and stop paths, including command preprocessing.
- Prevented duplicate permission-denial and unknown-command responses for denied namespaced start commands.

The safety implementation was completed in #143, #144, and #145.

## Automated verification

- `./gradlew clean test shadowJar --no-daemon`
- GitHub Actions checks for the three safety pull requests completed successfully before merge.
- The release-preparation build verifies the version embedded in `plugin.yml` and the versioned Shadow JAR name.

## Publication gates

Publication remains blocked until the exact final versioned candidate completes:

- disconnect during `COUNTDOWN`, followed by cleanup and recovery;
- mechanical before/after comparison proving zero block changes in the protected normal-world test region;
- the complete clean-start, restart, lifecycle, placement, permission, return, and recovery runtime matrix;
- a separate distribution metadata and third-party notices review.

## Scope

- This release does not add `/treasurerun create` or `/treasurerun join`.
- It does not change i18n behavior, translation wording, language files, ResourcePack content, database behavior, ranking behavior, README, or existing external-review records.
- The server-hosted create/join flow remains a separate later milestone.
