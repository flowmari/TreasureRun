# TreasureRun v0.2.1-alpha — Operator and replay follow-up

This document records the published release notes for v0.2.1-alpha.

## Included from already-merged work

- Configurable administrator update notifications (#174 / PR #180).
  - Disabled by default.
  - Version lookup is asynchronous and cached.
  - The version source is TreasureRun's GitHub Releases feed; the displayed message and destination
    link are operator-configurable.
- Post-round Play Again and configurable Hub actions (#175 / PR #181).
  - Play Again is offered only after authoritative cleanup and creates/joins a new WAITING session.
  - Hub is disabled by default and uses an operator-configured player-side command.
- Shared ranking query boundary (PR #182).
  - This is an internal reuse boundary; it does not by itself add `/treasurerun top`.
- Safe administrator force-start (#176 / PR #183).
  - `/treasurerunadmin forcestart` preserves the normal roster lock, minimum-player requirement,
    durable return preparation, arena preparation, teleport, and cleanup contracts.
  - It skips only the scheduled 10-second countdown wait before entering the same RUNNING runtime.

## Arena ownership and preparation hardening

- A world named `treasurerun_arena` is no longer accepted as plugin-owned by name alone.
- TreasureRun requires an ownership marker bound to the arena world's UUID before configuring or
  mutating an existing same-name world.
- An unmarked same-name world/directory fails closed instead of being silently adopted.
- The fixed 129 x 129 base water area is prepared once and recorded with a persistent preparation
  marker instead of being rebuilt on every round.
- Large defensive fallback area scans were removed from the normal round setup/cleanup hot path.
  Exact registered difficulty locations and the moving-safety-zone task's own restoration tracking
  remain the authoritative normal cleanup paths.

## Map requirement

No external or DeathRun map is required for this one-arena alpha. TreasureRun creates and uses the
dedicated `treasurerun_arena` world and builds the current test stage there.

Custom/prebuilt arena maps are not supported by this one-arena release. They belong to the later
ArenaRegistry / multi-arena architecture so generated and operator-provided arenas can have explicit
ownership and lifecycle metadata.

## Upgrade note from v0.2.0-alpha

v0.2.0-alpha created `treasurerun_arena` before the ownership marker existed. v0.2.1-alpha does not
silently claim an unmarked same-name directory.

Before first v0.2.1-alpha startup on a test server that has a v0.2.0-alpha arena:

1. Stop the server.
2. Back up the server and the existing `treasurerun_arena` directory.
3. If that directory is the disposable TreasureRun-generated alpha arena, rename or remove that
   backed-up arena directory so v0.2.1-alpha can create a freshly marked arena.
4. If ownership of an existing `treasurerun_arena` directory is uncertain, do not delete it;
   resolve the name collision before enabling TreasureRun.

## Not included in this release boundary

- `/treasurerun top` (#177).
- Optional leaderboard placeholders (#178).
- Custom/prebuilt map registration.
- ArenaRegistry or multiple arenas.
- AutoQueue or timed Auto Mode.
- Next-available-arena routing.

Those remain separate follow-up work and are not represented as completed here.
